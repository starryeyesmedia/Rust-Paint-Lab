# Next milestone plan: minimal replay-fed wgpu canvas

This is the historical plan agreed after Phase 3. Phase 4 implements the separate
replay canvas described in [canvas-demo.md](canvas-demo.md); shared routing remains
graphics-independent. No GPU code was part of the Phase 3 routing commit.

## Goal

Open one desktop window and visibly display strokes generated by the existing
Replay -> Processor -> Router pipeline. Start with synthetic input, not a live
pen requirement. Keep paint-input and paint-stroke unchanged and graphics-free.

## Implementation sequence

1. Investigate and pin compatible wgpu/windowing versions against Rust 1.90 and
   Windows 10/Iris Xe. Check maintenance, licenses, feature flags, surface ownership,
   and Linux/macOS compilation before committing to dependencies. Decide whether
   the spike needs winit; do not add egui panels in this milestone.
2. Add a separate canvas demo binary owning its single window/event loop, GPU
   device, surface, resize handling, and basic recoverable surface errors. Keep
   the existing native stylus diagnostic as a separate executable.
3. Feed an existing fixture and a deliberately cancelled fixture through the
   real replay/router path. Convert document-space command samples into a simple
   fixed-width polyline mesh with explicit finite/range checks at the f64-to-GPU
   boundary. This is demo geometry, not a brush or natural-media engine.
4. Keep per-StrokeId provisional geometry separate from committed demo geometry.
   Show commands progressively with an explicit demo cursor (independent of the
   deterministic command generator). Begin/Update show previews; Commit retains
   the result; Cancel removes the preview. Include two concurrent pointer IDs and
   touch activity so the demo proves independent previews and reserved touch.
5. Document build/run and GPU-backend diagnostics. Preserve shared tests, the
   existing Windows diagnostic artifact, and platform build checks. Package the
   canvas separately only if explicitly included in that task's scope.

## Acceptance checks

- Existing routing/replay tests remain unchanged and passing on all desktop CI.
- CPU command-to-demo-geometry tests verify transformed positions, bounds, final
  sample handling, independent IDs, and cancellation cleanup without a GPU.
- A supported offscreen GPU smoke test renders a known command stream and checks
  meaningful pixel regions; absence of an adapter must be reported as skipped or
  unavailable, not called a successful GPU test. Avoid bit-exact cross-driver
  image expectations. Decide explicitly which CI runner supplies a test adapter.
- Manual window test displays a committed replay stroke and an interrupted preview
  that disappears; resize and close work. Record actual backend/adapter evidence.
- Windows/Iris Xe and other hardware behavior is claimed only when actually run.
  Physical stylus testing remains independent; no live input adapter is required
  for this replay canvas milestone.

## Exclusions

No layers, full painting controls, live pen integration, undo/persistence, brush
simulation, exports, gestures, vector tools, or pressure-based brush design.
No commitment to a final document representation is implied by demo geometry.
